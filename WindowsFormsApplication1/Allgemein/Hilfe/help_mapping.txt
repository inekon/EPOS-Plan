# ===========================================================================
# help_mapping.txt - Zuordnung Steuerelement -> Hilfeseite im Wiki
# ===========================================================================
#
# Diese Datei ist die EINZIGE Stelle, an der Hilfe gepflegt wird. Sie wird als
# eingebettete Ressource mitgeliefert (F2). Eine gleichnamige Datei NEBEN DER
# EXE uebersteuert die eingebettete Fassung vollstaendig - damit lassen sich
# Zuordnungen ohne Neubau korrigieren.
#
# Seit H3 gilt das woertlich: ein neuer Infobutton braucht KEINE Zeile
# Programmtext mehr. HilfeAutomatik (Allgemein\Hilfe\HilfeAutomatik.cs) erfasst
# jedes geoeffnete Formular und jedes nachgeladene UserControl von selbst (F5);
# es genuegt, hier eine Zeile zu ergaenzen. Der Infobutton muss dafuer nur mit
# "btn_Help" beginnen.
#
# Kodierung: UTF-8 (mit BOM). Beim Bearbeiten UTF-8 beibehalten - seit H2
# stehen Umlaute nicht mehr nur in den Kommentaren, sondern auch in den ZIELEN
# ("Waermebedarf" heisst als Kurzname "Wärmebedarf").
#
# ---------------------------------------------------------------------------
# Format (H2, Konzept Hilfesystem/Wikidokumentation, A3)
# ---------------------------------------------------------------------------
#
#   Praefix.Controlpfad = Kurzname[#anker]
#
#   Praefix       Name des Formulars (Form.Name) bzw. der Name, mit dem
#                 RegisterControl(container, name) aufgerufen wird.
#   Controlpfad   Name des Steuerelements. Zwischencontainer duerfen mit
#                 Punkten angegeben werden (ucPanel.btn_Help); die Suche
#                 laeuft ohnehin rekursiv ueber alle Ebenen.
#   Kurzname      Der Titelteil hinter "Programm Dokumentation/" der Wiki-
#                 Unterseite, die der Button oeffnen soll - also z. B.
#                 "Klimadaten" fuer
#                 https://wiki.epos-plan.de/wiki/Programm_Dokumentation/Klimadaten
#   #anker        Optional: eine Sprungmarke innerhalb der Seite
#                 ({{Anker|...}} im Wiki). Sie wird VOR der Katalogaufloesung
#                 abgetrennt und beim Oeffnen wieder angehaengt.
#
# ---------------------------------------------------------------------------
# Was sich mit H1/H2 geaendert hat
# ---------------------------------------------------------------------------
#
# 1. EIN Ziel je Zeile. Die frueher zweite Haelfte "| en-ziel" entfaellt: Es
#    werden keine englischen Wiki-Seiten gepflegt. Bei englischer Oberflaeche
#    leitet die Anwendung dieselbe Seite beim Oeffnen durch den
#    Uebersetzungs-Proxy (Entscheid 7.1a, Allgemein\Hilfe\DokuUebersetzung.cs).
#    Der Parser versteht die Paarform weiterhin - eine aeltere Datei neben der
#    EXE laeuft also nicht auf einen Fehler.
#
# 2. Kein WordPress mehr. Slugs und Link-Pfade von epos-plan.de sind ersatzlos
#    verworfen; es wurde nichts konvertiert. Der Katalog kennt ausschliesslich
#    die Unterseiten der Rubrik "Programm Dokumentation" - er laedt sie ueber
#    api.php?action=query&list=allpages&apprefix=Programm%20Dokumentation%2F.
#
# 3. Abgleich ueber die Kleinschreibform. Katalog-Kurzname und Mapping-Ziel
#    laufen beide durch WikiHelpCatalog.SlugNormalisieren (Trim +
#    ToLowerInvariant) - "Wärmebedarf", "wärmebedarf" und " Wärmebedarf "
#    treffen dieselbe Seite. Umlaute bleiben dabei Umlaute.
#
# 4. Zeilen ab '#' AM ZEILENANFANG sind Kommentar (nach Abzug von BOM,
#    Leerzeichen und Tabulatoren), Leerzeilen werden uebersprungen. Ein '#'
#    MITTEN in einer Zeile ist seit H2 die Sprungmarke und kein Kommentar.
#
# ---------------------------------------------------------------------------
# Vertragsliste
# ---------------------------------------------------------------------------
# 26 Infobuttons zeigen auf 23 Unterseiten. Das Gegenstueck steht im Wiki auf
# der Rubrikseite "Programm Dokumentation", Abschnitt "Hilfeseiten" - wer eine
# Seite umbenennt, sieht dort, was daran haengt. Umbenennungen im Wiki nur MIT
# bleibender Weiterleitung: ein ausgeliefertes Programm traegt diese Datei
# eingebettet bei sich und altert bis zum naechsten Release.
#

# Feldgenaue Hilfe (H12)
# ===========================================================================
# Ab hier stehen KEINE Infobuttons mehr, sondern EINGABEBEREICHE der grossen
# Dialoge: GroupBoxen, Panels und Feldbeschriftungen. Ueberfahren zeigt
# dasselbe Popup wie beim Infobutton, der Verweis oeffnet die Rubrikseite des
# Dialogs an der passenden Sprungmarke (Abschnitt "Eingaben").
#
# Vier Regeln, nach denen diese Zeilen entstanden sind:
#
# 1. ZIELSEITE ist IMMER die Rubrikseite des Dialogs - dieselbe, die sein
#    btn_Help oeffnet. Eine Feldzeile verschiebt nie das Kapitel, sie
#    verfeinert nur die Stelle darin.
#
# 2. NUR NICHT BEDIENBARE Steuerelemente: GroupBox, Panel/FlowLayoutPanel/
#    TableLayoutPanel und Beschriftungen. Der Extender haengt sich auf Click,
#    und ein angeheftetes Popup auf einem Knopf, einem Kontrollkaestchen oder
#    einem Eingabefeld stuende der eigentlichen Bedienung im Weg. Ein Feld
#    wird deshalb ueber SEINE BESCHRIFTUNG angesprochen, nicht ueber das
#    Eingabefeld selbst.
#
# 3. NUR SICHTBARE Steuerelemente. Stillgelegtes bleibt aussen vor -
#    Wizard_WPItem.groupBox1 und die entfernten Modulkostenfelder. (Die vier
#    stillgelegten Steuerelemente von Form_Simulation_Config sind mit der Maske
#    selbst gefallen - iU9-W10b.1.)
#
# 4. EIN Anker darf mehrfach vorkommen. Drei Schwellenbeschriftungen zeigen
#    bewusst auf denselben Stichpunkt; zwei Ferien-Gruppen ebenso.
#
# Ein Feld, dessen Ziel der Katalog (noch) nicht kennt, bleibt STILL: kein
# Popup - aber es wird niemals abgeschaltet oder optisch veraendert. Diese
# Grenze zieht HelpExtender.SteuerelementAbschalten ueber IstInfobutton (H12);
# ohne sie nimmt ein GroupBox.Enabled = false jedem Feld darin die Bedienung.
#
# Die Sprungmarken selbst werden im Wiki in einem Sammelimport gesetzt
# ({{Anker|...}}). Bis dahin loest jede Zeile auf SEITENEBENE auf - der Sprung
# landet oben auf der Seite, der Verweis funktioniert.
# ---------------------------------------------------------------------------

# --- Bericht: UcBericht ---------------------------------------------------
# Das UserControl hing im Reiter "Berichte & Kosten"; die Zeilen galten ueber
# sein eigenes Praefix. Die Dialoghuelle Form_Bericht ist mit iU9-W0 entfallen,
# das UserControl selbst mit iU9-W5.6 (Nachfolge: die Razor-Komponente
# BerichtSeite).
#
# DIE VIER FELDZEILEN SIND SEITHER OHNE ANSCHRIFT. Der HelpExtender haengt
# seine Anker an WinForms-Steuerelemente; eine Razor-Seite fuehrt EINEN
# Infoknopf (UcBericht.btn_Help, oben) statt vier Feldanker. Die Zeilen bleiben
# stehen, weil sie die Wikiabschnitte benennen - sie werden wieder gebraucht,
# sobald die Seite je Abschnitt einen eigenen Infoknopf bekommt.
UcBericht.lblVarianten = Bericht#varianten
UcBericht.lblBausteine = Bericht#bausteine
UcBericht.lblAusgabe   = Bericht#ausgabeformat
UcBericht.lblZiel      = Bericht#zielordner

# --- Nicht aufgenommen (Befunde, siehe H12-Protokoll) ---------------------
# UcBkKosten            baute seine Oberflaeche im Code auf und setzte an
#                       KEINEM Kind einen Namen - ohne Control.Name gab es
#                       keine Anschrift. Mit iU9-W5.6 ist die Maske geloescht;
#                       die Nachfolge KostenSeite traegt EINEN Infoknopf
#                       (UcBkKosten.btn_Help).
# ErzeugerKarte /       UserControls ohne Namen. Sie sind zugleich die Grenze
# SpeicherKarte         der Tiefensuche - erst ein (ID-abhaengiger) Name macht
#                       Quellprofil, Waermequelle und Betriebsmodus feldgenau
#                       ansprechbar.
